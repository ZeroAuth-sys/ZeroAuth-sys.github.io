01 Background

This project came out of the Footprinting module in HTB Academy, specifically the passive reconnaissance section. The module walks through manual use of crt.sh, Shodan, and other OSINT sources — but doing it by hand is slow, inconsistent, and doesn't scale.

I wanted a tool that could hit all these sources automatically, deduplicate the results, and spit out a report I could actually read later. The secondary goal was to schedule it as a cronjob so I'd get a weekly snapshot of a target's exposure — useful for tracking changes over time, which matters a lot in real engagements.

This is entirely passive. No packets sent to the target, no port knocks, no active probing of any kind. Everything is queried from third-party aggregators that have already indexed the target.

! LEGAL Passive recon against a domain you don't own or have explicit permission to test can still have legal implications depending on jurisdiction and how you use the data. Always operate within your authorized scope.

02 Objectives

  • Automate subdomain enumeration via certificate transparency logs (crt.sh)
  • Pull exposed services, ports, and banners from Shodan without touching the target
  • Query GrayHatWarfare for exposed S3 buckets and cloud storage assets
  • Scrape LinkedIn and GitHub for employee names, tech stack hints, and accidental credential leaks
  • Deduplicate and merge all results into a single structured dataset
  • Generate a readable, self-contained HTML report with dark theme
  • Schedule as a cronjob for continuous monitoring with delta highlighting

04 Data Sources

Each collector hits a different part of a target's passive footprint. Together they build a surprisingly complete picture with zero active probing.

crt.sh
Certificate Transparency log search. Every SSL/TLS cert issued for a domain is logged publicly. Great for surfacing subdomains that never appear in DNS or search results.
→ subdomains, wildcard certs, issuers
Shodan
Internet-wide scan aggregator. Queries Shodan's indexed data for IPs associated with the target — exposed ports, service banners, software versions, and vulnerabilities.
→ open ports, banners, CVEs, ASN data
GrayHatWarfare
Public cloud storage bucket search. Finds S3, Azure Blob, and GCS buckets associated with a target keyword — often contain sensitive files left publicly accessible.
→ public buckets, exposed file listings
GitHub OSINT
Searches GitHub for repos, gists, and commit history referencing the target domain. Often surfaces leaked API keys, internal hostnames, and technology stack information.
→ leaked secrets, internal hostnames, tech stack

05 Implementation

Main entrypoint

recon.py python
import yaml, json, argparse
from datetime import datetime
from collectors import crtsh, shodan, ghw, github
from processor import deduplicate, enrich
from reporter import generate_html

def run(target, config):
    results = {"target": target, "timestamp": datetime.now().isoformat()}

    print(f"[*] Running passive recon on: {target}")
    results["subdomains"] = crtsh.collect(target)
    results["services"] = shodan.collect(target, config["shodan_key"])
    results["buckets"] = ghw.collect(target)
    results["github"] = github.collect(target, config["gh_token"])

    results = deduplicate(enrich(results))
    generate_html(results, target)
    print(f"[+] Report saved → output/{target}_recon.html")

crt.sh collector

The crt.sh collector queries the certificate transparency search API, parses the JSON response, and extracts unique subdomain names. It handles wildcard certs and deduplicates via a set before returning.

collectors/crtsh.py python
import requests, json

def collect(domain):
    url = f"https://crt.sh/?q=%.{domain}&output=json"
    resp = requests.get(url, timeout=15)
    data = resp.json()

    subdomains = set()
    for entry in data:
        for name in entry["name_value"].split("\n"):
            name = name.strip().lstrip("*.")
            if domain in name:
                subdomains.add(name)

    print(f" [crt.sh] Found {len(subdomains)} subdomains")
    return sorted(subdomains)
i NOTE crt.sh occasionally rate-limits or times out under load. The collector wraps the request in a retry loop with exponential backoff. Three retries with 2s / 4s / 8s delays handles most transient failures.

Shodan collector

The Shodan collector resolves the target domain to its IPs, then queries the Shodan API for each. It extracts open ports, service banners, OS guesses, and any known CVEs from Shodan's vuln data.

collectors/shodan.py (excerpt) python
import shodan, socket

def collect(domain, api_key):
    api = shodan.Shodan(api_key)
    ip = socket.gethostbyname(domain)
    host = api.host(ip)

    return {
        "ip": host["ip_str"],
        "org": host.get("org", "unknown"),
        "ports": host["ports"],
        "vulns": list(host.get("vulns", {}).keys()),
        "data": [{"port": s["port"], "banner": s["data"][:200]}
                 for s in host["data"]]
    }

06 HTML Report

The reporter generates a single self-contained HTML file — all CSS and data inlined, no external dependencies. This means the report works offline, can be emailed, and doesn't leak the target domain to third-party CDNs.

  • Summary card at the top: total subdomains, open ports, exposed buckets, GitHub hits
  • Collapsible sections for each data source with sortable tables
  • Color-coded severity for Shodan vulns (critical → red, medium → amber)
  • Delta highlighting when comparing two runs — new findings shown in green, removed in red
  • Dark theme throughout, optimized for reading during late-night lab sessions

07 Scheduling with Cron

The tool runs on a weekly cronjob on my Ubuntu homelab server. Each run saves a timestamped JSON file, and the reporter automatically diffs against the previous run to highlight new findings.

crontab -e cron
# Run passive recon every Sunday at 03:00
0 3 * * 0 cd /opt/passive-recon && python recon.py \
  --target acme.com \
  --config config.yaml \
  --diff \
  >> /var/log/recon.log 2>&1
✓ TIP Store API keys in environment variables rather than config.yaml, and add config.yaml to .gitignore. Even "private" repos should never contain API keys — GitHub's secret scanning will catch it, but you'll still have rotated a key unnecessarily.

09 Lessons Learned

// 01
Rate limiting is real
crt.sh and GrayHatWarfare both rate-limit aggressively. Exponential backoff with jitter was essential — naive retries just hammer the rate limiter harder.
// 02
Dedup earlier, not later
Running deduplication per-collector rather than only at the merge step cuts API calls significantly. crt.sh returns a lot of duplicate entries from wildcard certs.
// 03
GitHub OSINT is underrated
The GitHub collector consistently surfaces the most interesting findings — internal hostnames, hardcoded credentials, and infrastructure details that don't show up anywhere else.
// 04
Self-contained HTML matters
Reports with external CDN dependencies leak the target domain in referer headers. Inlining all CSS eliminated this. An artifact of an engagement should never phone home.
