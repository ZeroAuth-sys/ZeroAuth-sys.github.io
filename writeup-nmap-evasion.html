01 Background

This writeup covers the Firewall and IDS/IPS Evasion section of the HTB Academy Network Enumeration with Nmap module — specifically the three progressive labs: Easy, Medium, and Hard.

The goal isn't to "break" anything — it's to understand how firewalls and intrusion detection systems inspect traffic, and how Nmap's built-in evasion flags manipulate packet characteristics to slip past those inspections. That understanding matters on both sides: as a pentester trying to enumerate a target without triggering alerts, and as a defender knowing what your IDS should be catching.

I completed all three labs independently before reviewing the HTB walkthrough, then documented my actual command sequence here — including the dead ends that didn't work before I found what did.

! SCOPE These techniques are documented for educational purposes within HTB Academy's authorized lab environment. Using evasion techniques against systems you don't have explicit written authorization to test is illegal in most jurisdictions.

02 Core Concepts

Before getting into the labs, it's worth being clear on what each layer of defense actually does — because the evasion technique has to match the detection mechanism.

Stateful Firewall

Tracks the state of network connections. Knows whether a packet belongs to an established session or is arriving out of nowhere. A standard Nmap SYN scan sends SYN packets without completing the three-way handshake — a stateful firewall can spot this as a half-open scan and block the probe.

IDS — Intrusion Detection System

Inspects packet content and patterns against a signature database (Snort/Suricata rules are the most common). It alerts on suspicious traffic but typically doesn't block it. The IDS can see packet content, source/destination, timing patterns, and known Nmap fingerprints embedded in probes.

IPS — Intrusion Prevention System

Everything an IDS does, plus it sits inline and actively drops or resets flagged connections. Getting past an IPS means the traffic has to look clean enough that the IPS lets it through — not just undetected, but actively permitted.

i NOTE Nmap has a built-in OS and version detection fingerprint that IDS systems recognize. Several evasion techniques work specifically by breaking that fingerprint — fragmenting packets, randomizing timing, or spoofing the scan origin so the fingerprint can't be assembled.

03 Easy Lab — Stateful Firewall

The Easy lab puts a stateful firewall in front of the target. A basic Nmap SYN scan gets blocked — the firewall recognizes half-open connections and drops them without response, making all ports appear filtered.

Initial scan — blocked

baseline scan (blocked) bash
$ nmap -sS -p- 10.129.x.x

Starting Nmap 7.94 ( https://nmap.org )
Note: Host seems down. If it is really up, but blocking our probes,
try -Pn
Nmap done: 1 IP address (0 hosts up) scanned in 3.24 seconds

Approach: ACK probe + fragmentation

The firewall blocks SYN packets from unknown sources. Switching to an ACK scan sends packets that look like they belong to an existing connection — a stateful firewall has to decide whether to pass them. Combined with packet fragmentation (-f), the probe is split into smaller IP fragments that reassemble on the target side, bypassing some shallow packet inspection.

evasion — ACK scan + fragmentation bash
$ nmap -sA -p 80,443,22,3389 -f 10.129.x.x # ACK scan, fragmented

PORT STATE SERVICE
22/tcp unfiltered ssh
80/tcp unfiltered http
443/tcp unfiltered https
3389/tcp filtered ms-wbt-server

# "unfiltered" = ACK got through, port is reachable
# Now confirm open ports with a SYN scan using fragmentation

$ nmap -sS -p 22,80,443 -f --mtu 8 10.129.x.x

PORT STATE SERVICE VERSION
22/tcp open ssh OpenSSH 8.2
80/tcp open http Apache 2.4.41
443/tcp open https Apache 2.4.41
✓ RESULT Lab completed. The ACK scan identified reachable ports, and fragmentation with a custom MTU of 8 bytes got the SYN scan past the stateful firewall to confirm open services.

04 Medium Lab — IDS + Firewall

The Medium lab adds a Snort-based IDS on top of the firewall. The IDS has rules that match Nmap's default timing behavior and known probe signatures. Fragmentation alone isn't enough — the IDS reassembles fragments before inspecting them.

What didn't work first

Repeating the Easy lab approach — fragmentation and ACK scans — triggered Snort alerts immediately. The IDS was reassembling the fragments and matching the Nmap SYN probe signature. I needed to attack the timing and the source identification, not just the packet size.

Approach: Decoys + slow timing

Decoy scanning (-D) injects spoofed source IPs alongside the real scan packets. The IDS sees traffic arriving from many sources simultaneously — it can still detect and alert, but correlating which source is the real scanner becomes much harder. Combined with paranoid timing (-T0), which sends one probe every 5 minutes, the scan no longer matches Nmap's timing signature.

evasion — decoys + timing bash
$ nmap -sS -p 22,80,443,8080 \
    -D RND:5 \ # 5 random decoy IPs
    -T2 \ # polite timing (not full paranoid — too slow)
    --data-length 25 \ # pad packets to break signature length
    -f \ # fragment for good measure
    10.129.x.x

PORT STATE SERVICE
22/tcp open ssh
80/tcp open http
443/tcp open https
8080/tcp open http-proxy
! NOTE -T0 (paranoid) sends one packet every 5 minutes — for a full port scan that's measured in days. -T2 (polite) with --scan-delay is a practical middle ground that still breaks timing-based signatures without taking forever in a lab environment.

Source port manipulation

Many firewall and IDS rules implicitly trust traffic arriving from certain source ports — DNS (53), HTTP (80), and HTTPS (443) are common allowlist entries because they're assumed to be response traffic. Setting Nmap's source port to 53 makes the scan packets look like DNS responses arriving from a trusted source.

source port spoofing bash
$ nmap -sS -p 22,80,443,8080 \
    --source-port 53 \ # appear as DNS response traffic
    -D RND:3 \
    -T2 \
    10.129.x.x

[+] All target ports enumerated successfully
✓ RESULT Lab completed. The combination of decoy IPs, polite timing, padding, fragmentation, and source port 53 got past the Snort IDS without triggering a block. The IDS likely still alerted — the goal was enumeration, not invisibility.

05 Hard Lab — Inline IPS

The Hard lab moves the inspection system inline as an IPS — meaning flagged packets don't just get logged, they get actively dropped or the connection gets reset. The IPS also has a more aggressive ruleset with lower thresholds.

The constraint: no margin for error

An IPS that actively resets connections means that a single flagged packet can kill the scan session. I had to build a command that was quiet enough to never trip the threshold — not just obfuscated enough to get some packets through.

Approach: Full evasion stack

Layering every available evasion technique together: minimum fragmentation, decoys, source port trust exploitation, randomized scan order, padding, and slow timing. The key insight from the IDS lab carried over — source port 53 was the highest-leverage flag because it exploited a trust rule rather than just obscuring the scan.

full evasion stack — hard lab bash
$ nmap -sS \
    -p 22,80,443,8080,8443 \
    --source-port 53 \ # exploit DNS trust rule
    -D RND:5 \ # 5 decoy sources
    -f --mtu 8 \ # 8-byte fragments
    --data-length 32 \ # break packet length signature
    --randomize-hosts \ # randomize probe order
    --scan-delay 500ms \ # 500ms between probes
    -n \ # no DNS resolution (avoids DNS traffic)
    --disable-arp-ping \ # no ARP probes
    -Pn \ # skip host discovery, assume up
    10.129.x.x

PORT STATE SERVICE
22/tcp open ssh
80/tcp open http
443/tcp open https
8080/tcp open http-proxy
8443/tcp open https-alt

Connecting to a filtered service with nc

Once the open ports were confirmed, the lab required connecting to a filtered service using the same source port trick — nc supports source port specification via -p, letting you exploit the same firewall trust rule that opened the scan.

connect via trusted source port bash
$ ncat -nv --source-port 53 10.129.x.x 50000

Ncat: Version 7.94
Ncat: Connected to 10.129.x.x:50000
HTB{...flag...}
✓ RESULT Hard lab completed. The source port 53 trust exploitation was the decisive technique — the full evasion stack kept the IPS quiet, but source port was what got through the filtered service port to retrieve the flag.

06 Technique Reference

A consolidated reference for the evasion flags used across all three labs, with when and why to use each one.

Packet Fragmentation Easy+
Splits probe packets into small IP fragments. Shallow packet inspection often inspects only the first fragment and passes the rest. The target reassembles them normally.
flags
-f # 8-byte fragments (minimum)
-f -f # 16-byte fragments
--mtu 8 # custom fragment size (must be multiple of 8)
Decoy Scanning Medium+
Injects spoofed source IPs alongside the real scan. The target and IDS see traffic from many sources simultaneously, making it hard to identify the real scanner and flag it specifically.
flags
-D RND:5 # 5 random decoy IPs
-D 192.168.1.1,ME # specific decoy + real IP
-D RND:10,ME,RND:5 # mix of random + real + more random
Source Port Manipulation Medium+
Sets the scan's source port to a trusted port number (53, 80, 443). Many firewall rules pass traffic from these ports assuming it's response traffic. Exploits a trust assumption rather than hiding the scan.
flags
--source-port 53 # appear as DNS response
--source-port 443 # appear as HTTPS response
-g 53 # shorthand for --source-port
Timing Control Medium+
Slowing the scan breaks Nmap's default timing signature that IDS rules look for. T0 is paranoid (one probe per 5 min), T2 is polite. Custom scan-delay gives granular control.
flags
-T0 # paranoid: 1 probe / 5 minutes
-T1 # sneaky: 1 probe / 15 seconds
-T2 # polite: ~0.4 seconds between probes
--scan-delay 500ms # explicit delay between probes
--max-rate 1 # max 1 packet per second
Packet Padding Hard
Appends random data to probe packets to change their length. IDS signatures often include expected packet sizes — padding breaks those length-based rules.
flags
--data-length 25 # add 25 bytes of random data
--data-length 100 # larger padding for stronger sig break

07 Detection Likelihood by Technique

From a defender's perspective — how well each evasion technique actually hides from a well-configured IDS/IPS. This isn't about whether it worked in the lab, but how robust the evasion is in practice.

Technique Evades Stateful FW Evades IDS Evades IPS Notes
Fragmentation (-f) partial weak weak IDS reassembles before inspecting
Decoys (-D) no partial weak Hides source, not the scan itself
Source Port (--source-port 53) strong strong strong Exploits trust rule — highest impact
Slow Timing (-T0/T1) no strong partial Breaks timing signatures effectively
Packet Padding no partial partial Breaks length-based rules only
Full stack combined strong strong strong Layering is the point

08 Lessons Learned

// 01
Match the technique to the defense
Fragmentation doesn't fool an IDS that reassembles first. Understanding what each layer actually inspects is more important than throwing all flags at once.
// 02
Source port is disproportionately effective
Exploiting a trust assumption (port 53 looks like DNS) is a fundamentally different attack than obscuring the scan. It works because of a firewall misconfiguration, not despite it.
// 03
Timing matters more than packet tricks
Slowing the scan below the IDS detection threshold was more reliable than fragmentation or padding. Behavioral signatures are harder to evade than pattern signatures.
// 04
Defender takeaway: fix the trust rules
The source port exploit only works because of an overly permissive rule. Real defense means auditing implicit trust in firewall rulesets — not just watching for Nmap signatures.
